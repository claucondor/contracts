# v0.8.2 Multi-Token Fix Sprint

**Date**: 2026-06-11
**Branch**: `feat/shielded-recovery` (same as v0.8.1)
**Trigger**: front bug — portfolio shows same shielded balance across FLOW, mUSDC, MockFT (duplicated). Operator wrap of 1 FLOW shows up as `1000000000000.0000 mUSDC` and `10000000000.0000 MockFT` (same `1e18` value divided by each token's decimals).

---

## Root Cause

`ShieldedCheckpoint.sol` and `ShieldedCheckpoint.cdc` use `mapping(address user => Checkpoint)` — **one slot per user, not per token**. When user wraps a second token, the new snapshot OVERWRITES the first. Front correctly reads the singleton blob but duplicates it across token rows.

**Why tests passed:**
- `smoke-flow.cjs`, `smoke-musdc.cjs`, `smoke-mockft.cjs` run independently — each is a single-token scenario
- `combo-A` (alice-diversified across 3 tokens) DOES wrap all 3, but **never decrypts the checkpoint** — only asserts on-chain `commitments[]` and inbox events (`grep checkpoint scripts/combo-*.cjs` → 0 hits)
- The actual user-facing decrypt → balance flow was never exercised in CI for multi-token

**Validation that the fix is needed:**
- `mapping(address => Checkpoint) private _checkpoints;` (line 42, ShieldedCheckpoint.sol)
- `function update(...)` writes `_checkpoints[msg.sender]` (line 94)
- No per-token differentiation anywhere in the primitive

## Fase A — Sub-phases (focused mini-agents, commits in between)

### A.1 — `ShieldedCheckpoint.sol` per-token

**Scope (one mini-agent):**
- `mapping(address user => mapping(address token => Checkpoint)) _checkpoints`
- `update(address token, bytes encryptedSnapshot, uint256 ephX, uint256 ephY, uint64 lastConsumedNoteIndex)` — token is first arg
- `read(address token)` view from `msg.sender`
- `metadata(address user, address token)` view
- Events: add `token` indexed field to `CheckpointUpdated`
- Bytecode + ABI built
- Solidity unit tests: per-token isolation (write FLOW slot, mUSDC slot stays empty), update overwrites only the per-token slot, metadata returns correct hasCheckpoint per token
- **NO vN naming** (per memory) — same contract name, new address

**Exit criteria:** 100% unit tests green. Contract source committed under `packages/shielded-recovery/contracts/solidity/ShieldedCheckpoint.sol` (in-place modify, not vN file).

### A.2 — `ShieldedCheckpoint.cdc` per-token

**Scope (one mini-agent):**
- Mirror A.1 changes in Cadence resource: per-token slots inside the user's account resource (or contract-level dict-of-dicts, follow existing Cadence pattern — see [[cadence-upgrade-no-new-fields]])
- Cadence test suite mirroring A.1 isolation + overwrite assertions
- Contract upgradeable via existing pattern (NO new top-level field — use resource pattern per memory)

**Exit criteria:** Cadence test suite green. Upgrade path documented.

### A.3 — Wire JanusFlow + JanusERC20 + JanusFT to per-token checkpoint

**Scope (one mini-agent):**
- `JanusFlow.sol` (EVM): UUPS upgrade — `_writeCheckpoint` (or equivalent) passes `address(this)` as token key
- `JanusERC20.sol` (EVM): UUPS upgrade — same pattern  
- `JanusFT.cdc` (Cadence): pass underlying token type as key when calling new ShieldedCheckpoint.cdc
- Wire ABIs in `cadence-crypto-lab`-style atomic patterns (Cadence-side calldata for `update(address,bytes,uint256,uint256,uint64)`)
- Existing per-token smoke tests (`smoke-flow.cjs`, `smoke-musdc.cjs`, `smoke-mockft.cjs`) ADAPTED to new API; still must pass

**Exit criteria:** all 3 per-token smokes green against new contract addresses.

### A.4 — Deploy + Multi-Token E2E

**Scope (one mini-agent):**
- Deploy new ShieldedCheckpoint EVM (fresh address — no UUPS, primitive is immutable per existing pattern)
- Deploy new ShieldedCheckpoint Cadence
- UUPS upgrade JanusFlow + JanusERC20 to wire new checkpoint addr
- Cadence upgrade JanusFT to wire new checkpoint
- Update `DEPLOYMENTS.md` with new addresses
- **NEW** `combo-F.cjs`: single user wraps all 3 tokens, reads + decrypts each per-token snapshot, asserts:
  - Each snapshot decrypts cleanly
  - Each balance matches the wrapped amount of THAT token (not the same value across all)
  - Per-token `metadata(user, token).hasCheckpoint` reflects which tokens were wrapped
- Update `tests/v0.8-smoke/smoke-admin-reset.cjs` to reset per-token if needed

**Exit criteria:**
- combo-F green
- All previous combo-A/B/C/D/E still green (regression)
- DEPLOYMENTS.md updated with new ShieldedCheckpoint EVM + Cadence addresses
- Commit log: per sub-phase, with `[A.1]` / `[A.2]` / `[A.3]` / `[A.4]` prefix
