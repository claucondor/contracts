# Janus Protocol v0.8 — SDK Integration Guide

> **Target:** SDK developers integrating against the v0.8 stack deployed on Flow EVM testnet.
> **Status:** All addresses verified on-chain. All patterns tested with real transactions (Phase 9.A/B/C/D, GREEN).
> **Branch:** `feat/shielded-recovery` — do not merge to main until SDK sprint is complete.

---

## 0. TL;DR — What Changed in v0.8

- **ShieldedInbox primitive** — a new content-agnostic on-chain mailbox (EVM + Cadence). Recipients no longer need to scan events; they drain their own inbox and ECIES-decode each note.
- **ShieldedCheckpoint primitive** — a new owner-only encrypted state store. Senders update their own checkpoint after transfers to enable fast balance recovery (cursor + encrypted snapshot).
- **`shieldedTransfer` dropped sender-snapshot params** — the old 9-arg signature is gone. The new signature has 6 args: `(to, publicInputs[6], proof[8], encryptedNoteTo, ephPubkeyToX, ephPubkeyToY)`. Sender state is managed separately via `ShieldedCheckpoint.update()`.
- **Inbox deposit is automatic** — `shieldedTransfer` calls `ShieldedInbox.deposit()` internally and atomically. The sender does NOT call the inbox directly.
- **`adminBatchResetSlots`** — new owner-only batch reset function (up to 100 slots), replacing the single-slot `adminResetSlot` for testnet cleanup.
- **All contracts freshly deployed** — new proxy addresses; v0.7.1 demo contracts remain live at their old addresses for backwards compatibility.

## 2. Architectural Concepts

### 2.1 Layer Separation

```
APP (PrivateTip / SDK consumer)
  │   provides: note schema, proof inputs, keypairs
  │
  ▼
SDK (@openjanus/sdk)
  │   provides: proof builders, ECIES, inbox/checkpoint clients, token adapters
  │
  ▼
CORE CONTRACTS (this repo)
  ├── JanusFlow / JanusERC20 / JanusFT   — commitment state machine (per-token)
  ├── ShieldedInbox                       — append-only mailbox (shared across tokens)
  ├── ShieldedCheckpoint                  — sender state recovery store (shared across tokens)
  ├── MemoKeyRegistry                     — BabyJub pubkey lookup (EVM-only)
  └── Verifiers                           — Groth16 proof verification (immutable)
```

Key design principle: **the contracts are schema-agnostic**. The inbox and checkpoint store opaque bytes. The SDK defines the note schema (`{v, amt, bld, memo?}`). Apps can extend or override the schema without contract changes.

### 2.2 Inbox + Checkpoint Pattern

**Why these primitives exist:**

- In v0.7.x, senders passed their encrypted snapshot as calldata in `shieldedTransfer`. This created a tight coupling and prevented sender-checkpoint updates from being composed atomically.
- In v0.8, the inbox and checkpoint are separate composable primitives.

**ShieldedInbox flow:**
1. Before Bob can receive a transfer, he installs `@ShieldedInbox.NoteInbox` to `/storage/shieldedInbox` and publishes a `&{Receiver}` capability at `/public/shieldedInbox`.
2. When Alice calls `shieldedTransfer(to=Bob, ...)`, the token contract automatically calls `ShieldedInbox.deposit(recipient=Bob, ciphertext=..., ephPubkeyX=..., ephPubkeyY=...)`.
3. Bob calls `inbox.drainBatch(N)` → receives `Note[]` array. Each note has `{ciphertext, ephPubkeyX, ephPubkeyY, depositor, blockNumber}`.
4. Bob ECIES-decodes each note with his BabyJub private key.
5. The `depositor` field tells Bob which token contract deposited the note, enabling multi-token disambiguation.

**ShieldedCheckpoint flow (sender-side):**
1. Alice installs `@ShieldedCheckpoint.Checkpoint` to `/storage/shieldedCheckpoint`.
2. After each transfer, Alice calls `checkpoint.update(encryptedSnapshot, ephX, ephY, lastConsumedNoteIndex)` — either in a separate transaction or atomically composed with the transfer (see `combined_shielded_transfer_with_checkpoint.cdc`).
3. The encrypted snapshot contains Alice's new `(value, blinding)` after the transfer, ECIES-encrypted to her own pubkey.
4. On a fresh device (wallet recovery scenario), Alice reads her latest checkpoint, decrypts it to recover `(value, blinding)`, and reconstructs her commitment state without scanning all history.

### 2.3 Multi-Token Coexistence

All three token contracts (JanusFlow, JanusERC20, JanusFT) share a **single** ShieldedInbox contract. Per-user state is isolated because:

- Each user's inbox is indexed by their address — `_inboxes[user]` on EVM, `NoteInbox` resource on Cadence.
- Each note has a `depositor` field containing the address of the token contract that called `deposit()`.
- Recipients distinguish which token a note belongs to by checking `note.depositor` against the known token contract addresses.
- Sending FLOW via JanusFlow does NOT affect the user's mUSDC balance in JanusERC20 — commitments are stored per-token-contract.

### 3.3 JanusFlow / JanusERC20 / JanusFT — Key Signatures

#### CRITICAL: v0.8 `shieldedTransfer` (6 args — dropped sender snapshot)

**EVM (inherited by both JanusFlow and JanusERC20):**
```solidity
function shieldedTransfer(
    address to,                      // recipient EVM address
    uint256[6] calldata publicInputs, // [C_old.x, C_old.y, C_tx.x, C_tx.y, C_new.x, C_new.y]
    uint256[8] calldata proof,        // [pA[2], pB[4], pC[2]] flat Groth16 proof
    bytes calldata encryptedNoteTo,   // ECIES ciphertext for recipient (auto-deposited to inbox)
    uint256 ephPubkeyToX,             // ephemeral pubkey X for recipient note
    uint256 ephPubkeyToY              // ephemeral pubkey Y for recipient note
) external
```

The `publicInputs` layout is fixed:
```
publicInputs[0] = C_old.x   // sender's current commitment X (must match on-chain state)
publicInputs[1] = C_old.y   // sender's current commitment Y
publicInputs[2] = C_tx.x    // transfer commitment X (amount being sent)
publicInputs[3] = C_tx.y    // transfer commitment Y
publicInputs[4] = C_new.x   // sender's new commitment X after transfer
publicInputs[5] = C_new.y   // sender's new commitment Y after transfer
```

**What happens automatically:** The contract verifies C_old matches on-chain state, verifies the Groth16 transfer proof, updates the sender's commitment to C_new, accumulates C_tx into the recipient's commitment (homomorphic add), and calls `shieldedInbox.deposit(to, encryptedNoteTo, ephPubkeyToX, ephPubkeyToY)`.

## 4. Pattern: Wrap (with Amount-Disclose Proof)

### 4.1 JanusFlow (FLOW) Wrap — Complete Example

This is the exact code from `tests/v0.8-smoke/smoke-flow.cjs` (Phase 9.A, tx `0x3e82d52d...`):

```js
const { ethers } = require("ethers");
const {
  generateAmountDiscloseProof,
  SUBORDER,
} = require("./helpers/proofGen.cjs");
const { encryptNote } = require("./helpers/ecies.cjs");

const JANUS_FLOW_ABI = [
  "function wrapWithProof(uint256 nonce, uint256[2] commit, uint256[2] pA, uint256[2][2] pB, uint256[2] pC, bytes encryptedSnapshot, uint256 ephPubkeyX, uint256 ephPubkeyY) payable",
];

// --- Proof generation ---
const wrapAmount   = 1n * 10n**18n;         // 1 FLOW in attoFLOW
const wrapBlinding = await randomScalar();  // random scalar mod SUBORDER
const wrapNonce    = BigInt(Date.now());    // must be unique per caller

const wrapProof = await generateAmountDiscloseProof({
  amount:   wrapAmount,
  blinding: wrapBlinding,
  nonce:    wrapNonce,
});
// wrapProof.pubSignals = [amount, commitX, commitY, nonce]
const commitX = wrapProof.pubSignals[1];
const commitY = wrapProof.pubSignals[2];

// --- Encrypt self-snapshot (for state recovery) ---
const { ciphertext: snapCipher, ephemeralPubkey: snapEph } = await encryptNote(
  { amount: wrapAmount, blinding: wrapBlinding },
  aliceJub.pubkey  // sender's own BabyJub pubkey
);

// --- Submit transaction ---
const janusFlow = new ethers.Contract(
  "0xA64340C1d356835A2450306Ffd290Ed52c001Ad3",
  JANUS_FLOW_ABI,
  signer
);

const tx = await janusFlow.wrapWithProof(
  wrapNonce,
  [commitX, commitY],
  wrapProof.pA,           // [pA[0], pA[1]]
  wrapProof.pB,           // [[pB[0][0], pB[0][1]], [pB[1][0], pB[1][1]]]
  wrapProof.pC,           // [pC[0], pC[1]]
  snapCipher,             // Buffer / Uint8Array
  snapEph.x,
  snapEph.y,
  { value: wrapAmount }   // FLOW amount as msg.value
);
const receipt = await tx.wait(1);
// On-chain: Alice's commitment = Commit(wrapAmount, wrapBlinding)
// totalLocked increases by wrapAmount
// Event: Wrapped(alice, wrapAmount)
```

## 5. Pattern: Shielded Transfer (with Inbox Auto-Deposit)

### 5.1 How It Works

1. Sender generates a Groth16 `confidential_transfer_aggregate` proof proving: "I have commitment C_old, I'm transferring C_tx to the recipient, and my new commitment is C_new."
2. Sender encrypts a note `{v:1, amt:"300000000000000000", bld:"<blinding>", memo:"..."}` to the recipient's BabyJub pubkey (ECIES).
3. Sender calls `shieldedTransfer(to, publicInputs, proof, encryptedNoteTo, ephX, ephY)`.
4. Contract updates sender commitment to C_new, accumulates C_tx into recipient's commitment, and **automatically** calls `ShieldedInbox.deposit(to, encryptedNoteTo, ephX, ephY)`.
5. Sender does NOT need to interact with the inbox directly.

### 5.2 Complete Example (EVM — JanusFlow)

From `tests/v0.8-smoke/smoke-flow.cjs` Step 4 (tx `0xa50351826a...`):

```js
const { generateProof } = require("./helpers/proofGen.cjs");
const { encryptNote }   = require("./helpers/ecies.cjs");

const transferAmount   = 3n * 10n**18n / 10n;  // 0.3 FLOW
const transferBlinding = await randomScalar();
const newSenderBlinding = await randomScalar();

// Generate transfer proof
const xferProof = await generateProof({
  old_value:         aliceV,         // sender's current balance (scalar)
  old_blinding:      aliceR,         // sender's current blinding
  transfer_value:    transferAmount,
  transfer_blinding: transferBlinding,
  new_blinding:      newSenderBlinding,
});
// xferProof.pubSignals = [C_old.x, C_old.y, C_tx.x, C_tx.y, C_new.x, C_new.y]

// Verify C_old matches on-chain state BEFORE submitting (gas-save check)
const [onchainCx, onchainCy] = await janusFlow.balanceOfCommitmentXY(senderAddress);
if (xferProof.pubSignals[0] !== onchainCx || xferProof.pubSignals[1] !== onchainCy) {
  throw new Error("C_old mismatch — fetch latest state before generating proof");
}

// Encrypt note for recipient
const memo = "payment for invoice #42";
const { ciphertext: noteCipher, ephemeralPubkey: noteEph } = await encryptNote(
  { amount: transferAmount, blinding: transferBlinding, memo },
  recipientBabyJubPubkey  // from MemoKeyRegistry.getMemoKey(recipientAddress)
);

// Build flat proof array [pA[0], pA[1], pB[0][0], pB[0][1], pB[1][0], pB[1][1], pC[0], pC[1]]
const flatProof = [
  xferProof.pA[0], xferProof.pA[1],
  xferProof.pB[0][0], xferProof.pB[0][1],
  xferProof.pB[1][0], xferProof.pB[1][1],
  xferProof.pC[0], xferProof.pC[1],
];

const tx = await janusFlow.shieldedTransfer(
  recipientAddress,
  xferProof.pubSignals.map(x => x),  // pubSignals is already 6-element array
  flatProof,
  noteCipher,
  noteEph.x,
  noteEph.y
);
await tx.wait(1);

// After the tx:
// - sender commitment = C_new (xferProof.pubSignals[4], [5])
// - recipient commitment += C_tx (homomorphic add)
// - recipient inbox count += 1
// - Event: ShieldedTransferNote(from, to, encryptedNoteTo, ephPubkeyToX, ephPubkeyToY)
// - Event: ConfidentialTransfer(from, to)

// Update sender's local state
aliceV = aliceV - transferAmount;
aliceR = newSenderBlinding;
```

### 5.3 Note Schema Convention (v3)

The note JSON schema is defined by the SDK (contracts are schema-agnostic):

```json
{"v":1,"amt":"300000000000000000","bld":"<blinding_decimal>","memo":"payment for invoice #42"}
```

Fields:
- `v` — schema version (always 1 for v0.8)
- `amt` — amount as decimal string (bigint.toString()), in the token's base units (attoFLOW for FLOW, token decimals for ERC20, UFix64 internal units * 1e8 for FT)
- `bld` — blinding scalar as decimal string
- `memo` — optional string (app-defined; contracts never read this)

Apps CAN add additional fields — contracts never parse the JSON. The SDK should pass through unknown fields transparently.

## 7. Pattern: Unwrap

The unwrap pattern requires TWO proofs: an amount-disclose proof (reveals the amount) and a transfer proof (demonstrates the sender has sufficient balance).

From `tests/v0.8-smoke/smoke-flow.cjs` Step 6 (tx `0xc9df878e...`):

```js
const { generateProof, generateAmountDiscloseProof } = require("./helpers/proofGen.cjs");

const unwrapAmount     = 7n * 10n**18n / 10n;  // 0.7 FLOW
const unwrapBlinding   = await randomScalar();   // blinding for the amount-disclose proof
const residualBlinding = await randomScalar();   // blinding for the residual commitment
const residualValue    = currentValue - unwrapAmount;

// Step 1: Amount-disclose proof (nonce=0 for unwrap — anti-replay via C_old state machine)
const amtProof = await generateAmountDiscloseProof({
  amount:   unwrapAmount,
  blinding: unwrapBlinding,
  nonce:    0n,         // ALWAYS 0 for unwrap
});
const txCommitX = amtProof.pubSignals[1];
const txCommitY = amtProof.pubSignals[2];

// Step 2: Transfer proof (proves sender has at least unwrapAmount)
const xferProof = await generateProof({
  old_value:         currentValue,
  old_blinding:      currentBlinding,
  transfer_value:    unwrapAmount,
  transfer_blinding: unwrapBlinding,   // must match amtProof's blinding
  new_blinding:      residualBlinding,
});

// IMPORTANT: C_tx must be consistent between the two proofs
// Both use the same (unwrapAmount, unwrapBlinding), so their commits are equal
if (xferProof.pubSignals[2] !== txCommitX || xferProof.pubSignals[3] !== txCommitY) {
  throw new Error("C_tx mismatch — use same blinding for both proofs");
}

// Step 3: Encrypt residual snapshot for self-recovery
const { ciphertext: residualSnap, ephemeralPubkey: residualEph } = await encryptNote(
  { amount: residualValue, blinding: residualBlinding },
  aliceJub.pubkey
);

const flatAmtProof  = [amtProof.pA[0], amtProof.pA[1], amtProof.pB[0][0], amtProof.pB[0][1], amtProof.pB[1][0], amtProof.pB[1][1], amtProof.pC[0], amtProof.pC[1]];
const flatXferProof = [xferProof.pA[0], xferProof.pA[1], xferProof.pB[0][0], xferProof.pB[0][1], xferProof.pB[1][0], xferProof.pB[1][1], xferProof.pC[0], xferProof.pC[1]];

const tx = await janusFlow.unwrap(
  unwrapAmount,
  recipientAddress,       // who receives the FLOW (can be msg.sender)
  [txCommitX, txCommitY],
  flatAmtProof,
  xferProof.pubSignals.map(x => x),  // 6-element transferPublicInputs
  flatXferProof,
  residualSnap,
  residualEph.x,
  residualEph.y
);
await tx.wait(1);
// FLOW is transferred to recipientAddress
// Sender commitment = C_new (xferProof.pubSignals[4], [5])
// totalLocked decreases by unwrapAmount
```

## 8. Pattern: Checkpoint Update (Sender-Side State)

The checkpoint is optional but strongly recommended for fast recovery. The canonical send pattern is to compose the transfer and checkpoint update atomically (see `combined_shielded_transfer_with_checkpoint.cdc` for Cadence).

For EVM users, the checkpoint is updated in a separate transaction:

```js
const SHIELDED_CHECKPOINT_ABI = [
  "function update(bytes encryptedSnapshot, uint256 ephPubkeyX, uint256 ephPubkeyY, uint64 lastConsumedNoteIndex)",
];

const checkpoint = new ethers.Contract(
  "0xbF8dbE133FC1319570dBe43E32BFD9a6D64E1E76",
  SHIELDED_CHECKPOINT_ABI,
  senderSigner
);

// After a shieldedTransfer, encrypt the NEW (value, blinding) state to sender's own pubkey
const { ciphertext, ephemeralPubkey } = await encryptNote(
  { amount: newSenderValue, blinding: newSenderBlinding },
  senderBabyJubPubkey
);

// lastConsumedNoteIndex = total notes the sender has drained from their OWN inbox
// (not the recipient's inbox). Used as a cursor for recovery.
const myInboxNotesCursor = 0n;  // sender hasn't drained their own inbox yet

await (await checkpoint.update(
  ciphertext,
  ephemeralPubkey.x,
  ephemeralPubkey.y,
  myInboxNotesCursor
)).wait(1);

// To recover state later:
// 1. Call checkpoint.read() (caller must be the owner — msg.sender == owner)
// 2. Decrypt encryptedSnapshot with your BabyJub privkey
// 3. Reconstruct commitment: Commit(decrypted.amount, decrypted.blinding)
```

## 11. ECIES Algorithm (Canonical)

This is the EXACT algorithm from `packages/janus-token/tests/solidity/helpers/ecies.cjs`. The SDK must implement this identically.

```js
/**
 * BabyJub ECIES + AES-256-GCM
 *
 * Construction:
 *   Encrypt:
 *     1. Generate ephemeral keypair on BabyJubJub subgroup (BASE8 generator).
 *     2. ECDH: shared = ephPriv · recipientPub (x-coordinate only).
 *     3. HKDF-SHA256(shared.x.toBytes32(), salt="openjanus/memo/v1"), output 32 bytes.
 *     4. AES-256-GCM encrypt with random 12-byte IV.
 *     5. Output: ciphertext = iv(12B) || ct || tag(16B); ephemeralPubkey = {x, y}.
 *
 *   Decrypt:
 *     1. ECDH: shared = recipientPriv · ephemeralPub (x-coordinate only).
 *     2. Same HKDF derivation.
 *     3. AES-256-GCM decrypt; throws on auth-tag failure.
 */

const { buildBabyjub } = require("circomlibjs");
const { webcrypto }    = require("crypto");

const SUBORDER    = 2736030358979909402780800718157159386076813972158567259200215660948447373041n;
const HKDF_SALT   = Buffer.from("openjanus/memo/v1", "utf8");
const IV_LEN      = 12;
const TAG_LEN     = 16;
const NOTE_VERSION = 1;

// --- BabyJub keypair ---
async function pubkeyFromPrivkey(privkey) {
  const bj = await buildBabyjub();
  const pt  = bj.mulPointEscalar(bj.Base8, privkey);
  return { x: BigInt(bj.F.toString(pt[0])), y: BigInt(bj.F.toString(pt[1])) };
}

async function generateKeypair() {
  const privkey = await randomScalar();
  return { privkey, pubkey: await pubkeyFromPrivkey(privkey) };
}

// --- ECDH ---
async function sharedSecret(privkey, peerPubkey) {
  const bj    = await buildBabyjub();
  const point = [bj.F.e(peerPubkey.x), bj.F.e(peerPubkey.y)];
  const shared = bj.mulPointEscalar(point, privkey);
  return BigInt(bj.F.toString(shared[0]));  // x-coordinate only
}

// --- HKDF → AES key ---
function fieldElemTo32Bytes(n) {
  return Buffer.from(n.toString(16).padStart(64, "0"), "hex");
}

async function deriveAesKey(secretX) {
  const ikm     = fieldElemTo32Bytes(secretX);
  const baseKey = await webcrypto.subtle.importKey("raw", ikm, "HKDF", false, ["deriveKey"]);
  return webcrypto.subtle.deriveKey(
    { name: "HKDF", hash: "SHA-256", salt: HKDF_SALT, info: new Uint8Array(0) },
    baseKey,
    { name: "AES-GCM", length: 256 },
    false, ["encrypt", "decrypt"]
  );
}

// --- Encrypt text ---
async function encryptText(plaintext, recipientPubkey) {
  const eph    = await generateKeypair();
  const secret = await sharedSecret(eph.privkey, recipientPubkey);
  const key    = await deriveAesKey(secret);

  const iv       = new Uint8Array(IV_LEN);
  webcrypto.getRandomValues(iv);
  const ctAndTag = new Uint8Array(
    await webcrypto.subtle.encrypt({ name: "AES-GCM", iv }, key, Buffer.from(plaintext, "utf8"))
  );
  return {
    ciphertext:    Buffer.concat([Buffer.from(iv), Buffer.from(ctAndTag)]),
    ephemeralPubkey: eph.pubkey,
  };
}

// --- Decrypt text ---
async function decryptText(ciphertext, ephemeralPubkey, privkey) {
  const buf    = Buffer.isBuffer(ciphertext) ? ciphertext : Buffer.from(ciphertext);
  const secret = await sharedSecret(privkey, ephemeralPubkey);
  const key    = await deriveAesKey(secret);
  const iv     = buf.subarray(0, IV_LEN);
  const ct     = buf.subarray(IV_LEN);
  const plain  = new Uint8Array(await webcrypto.subtle.decrypt({ name: "AES-GCM", iv }, key, ct));
  return Buffer.from(plain).toString("utf8");
}

// --- Note encode/decode ---
async function encryptNote(note, recipientPubkey) {
  const wire = { v: NOTE_VERSION, amt: note.amount.toString(), bld: note.blinding.toString() };
  if (note.memo !== undefined) wire.memo = note.memo;
  return encryptText(JSON.stringify(wire), recipientPubkey);
}

async function decryptNote(ciphertext, ephemeralPubkey, privkey) {
  const plain = await decryptText(ciphertext, ephemeralPubkey, privkey);
  const w     = JSON.parse(plain);
  if (!w || w.v !== NOTE_VERSION || !w.amt || !w.bld) {
    throw new Error("invalid note format");
  }
  const result = { amount: BigInt(w.amt), blinding: BigInt(w.bld) };
  if (w.memo !== undefined) result.memo = w.memo;
  return result;
}

module.exports = { generateKeypair, pubkeyFromPrivkey, sharedSecret, encryptText, decryptText, encryptNote, decryptNote, SUBORDER };
```

**TypeScript SDK implementation guidance:**
- Use `circomlibjs` for BabyJubJub operations (same as above).
- The `webcrypto.subtle` API is available in Node.js 18+ and all modern browsers natively — no polyfill needed.
- HKDF salt is `"openjanus/memo/v1"` (UTF-8, not hex).
- The ephemeral pubkey is ALWAYS on the BabyJubJub `Base8` generator subgroup.

```js
function commit(value, blinding) {
  // C = [value]*G + [blinding]*H
  const vG = pointMul(GX, GY, value  % SUBORDER);
  const rH = pointMul(HX, HY, blinding % SUBORDER);
  const [cx, cy] = babyAdd(vG[0], vG[1], rH[0], rH[1]);
  return { x: cx, y: cy };
}
```

### 12.5 `generateProof` (confidential transfer — for shieldedTransfer and unwrap)

```js
async function generateProof({ old_value, old_blinding, transfer_value, transfer_blinding, new_blinding }) {
  const oldCommit = commit(old_value,      old_blinding);
  const txCommit  = commit(transfer_value, transfer_blinding);
  const newValue  = old_value - transfer_value;
  const newCommit = commit(newValue,       new_blinding);

  const circuitInput = {
    old_value:         old_value.toString(),
    old_blinding:      old_blinding.toString(),
    transfer_value:    transfer_value.toString(),
    transfer_blinding: transfer_blinding.toString(),
    new_blinding:      new_blinding.toString(),
    old_commit:        [oldCommit.x.toString(), oldCommit.y.toString()],
    transfer_commit:   [txCommit.x.toString(), txCommit.y.toString()],
    new_commit:        [newCommit.x.toString(), newCommit.y.toString()],
  };
  const { proof, publicSignals } = await snarkjs.groth16.fullProve(
    circuitInput, CT_WASM_PATH, CT_ZKEY_PATH
  );
  return {
    pA: [BigInt(proof.pi_a[0]), BigInt(proof.pi_a[1])],
    pB: [
      [BigInt(proof.pi_b[0][1]), BigInt(proof.pi_b[0][0])],  // coords swapped
      [BigInt(proof.pi_b[1][1]), BigInt(proof.pi_b[1][0])],
    ],
    pC: [BigInt(proof.pi_c[0]), BigInt(proof.pi_c[1])],
    pubSignals: publicSignals.map(BigInt),
    // pubSignals[0,1] = C_old.x,y  [2,3] = C_tx.x,y  [4,5] = C_new.x,y
  };
}
```

**`pB` coordinate swap note:** snarkjs returns `pi_b[0] = [y1, x1]` (y-first). The EVM verifier expects `[x, y]` order. The swap `pB[i] = [pi_b[i][1], pi_b[i][0]]` is applied in the proof builder. The Cadence JanusFT wrapper ALSO applies this swap internally when calling the EVM verifier — so when calling JanusFT, pass `pB` as returned by the proof builder (the Cadence side handles the re-ordering).

## 15. Edge Cases + Known Limitations

| Issue | Severity | Detail |
|---|---|---|
| **`totalLocked` Cadence read gap** | Cosmetic | `JanusFT.totalLocked` is `UFix64` (8 decimals) but the circuit tracks value in UInt256 (raw integer * 1e8). When reading via REST script, the UFix64 string like `"100.00000000"` is correct for display but must be multiplied by `1e8` before comparing with circuit values. |
| **Inbox full reverts transfer** | Behavioral | If `count(recipient) >= MAX_INBOX_NOTES (10000)`, the transfer reverts. Recipient must drain their inbox. The SDK should check inbox capacity before submitting a transfer and warn the app if headroom is low. |
| **Snapshot size limit** | Behavioral | `encryptedSnapshot` must be ≤ 16384 bytes (16 KB). The JSON note schema is ~100 bytes; this limit is only a concern if apps add large custom fields. |
| **Batch claim circuit lacks NoteCommitmentTracker** | Mainnet-blocker | `ConfidentialClaimBatchVerifier` is deployed but the circuit does not track consumed note commitments, allowing replay attacks. Do NOT use batch claim in production. Expose as `@experimental` in the SDK. |
| **COA ownership for EVM admin** | Architecture note | The EVM proxies are owned by the COA (`0x000...020885d7ad...`), not an EOA. All `adminBatchResetSlots` calls must go through the COA via a Cadence transaction (`admin_evm_call.cdc`). Direct EOA admin calls will fail with `"Ownable: caller is not the owner"`. |
| **JanusFT BabyJub verifiers are different from JanusFlow verifiers** | Architecture note | JanusFT uses the v0.7 aggregate verifiers at `0x5702A5...` and `0xa80283...` (embedded as constants in the contract). JanusFlow/ERC20 use the v0.8 re-deployed verifiers at `0x38e69f...` and `0xf7B634...`. The underlying circuits are identical; only the deployment addresses differ. |
| **Cadence `firstSnapshot` event gap** | Minor | If `JanusFT.commitments[account] == nil` check runs before state write (correct behavior), `FirstSnapshot` fires. But sender always has a commitment before transfer (they have C_old). So `senderWasFresh` check in shieldedTransfer is theoretically always `false` for the sender path. No functional impact. |

```js
  const memoRegBob  = new ethers.Contract(ADDRESSES.memoKeyRegistry,  MEMO_KEY_REGISTRY_ABI, bobSigner);
  const inboxBob    = new ethers.Contract(ADDRESSES.shieldedInbox,    SHIELDED_INBOX_ABI,    bobSigner);

  // 1. Generate keypairs
  const aliceJub = await deriveJubKeypair(aliceSigner.address);
  const bobJub   = await deriveJubKeypair(bobSigner.address);

  // 2. Publish memokeys
  await (await memoReg.publishMemoKey(aliceJub.pubkey.x, aliceJub.pubkey.y)).wait(1);
  await (await memoRegBob.publishMemoKey(bobJub.pubkey.x, bobJub.pubkey.y)).wait(1);

  // 3. Wrap 1 FLOW
  const wrapAmt      = 1n * 10n**18n;
  const wrapBlinding = await randomScalar();
  const wrapNonce    = BigInt(Date.now());
  const wrapProof    = await generateAmountDiscloseProof({ amount: wrapAmt, blinding: wrapBlinding, nonce: wrapNonce });
  const { ciphertext: snapC, ephemeralPubkey: snapEph } = await encryptNote({ amount: wrapAmt, blinding: wrapBlinding }, aliceJub.pubkey);
  await (await janusFlow.wrapWithProof(
    wrapNonce, [wrapProof.pubSignals[1], wrapProof.pubSignals[2]],
    wrapProof.pA, wrapProof.pB, wrapProof.pC, snapC, snapEph.x, snapEph.y,
    { value: wrapAmt }
  )).wait(1);

  // Track Alice state
  let aliceV = wrapAmt, aliceR = wrapBlinding;

  // 4. ShieldedTransfer 0.3 FLOW → Bob
  const xferAmt  = 3n * 10n**18n / 10n;
  const xferBld  = await randomScalar();
  const newAliceR = await randomScalar();
  const xferProof = await generateProof({ old_value: aliceV, old_blinding: aliceR, transfer_value: xferAmt, transfer_blinding: xferBld, new_blinding: newAliceR });
  const { ciphertext: noteC, ephemeralPubkey: noteEph } = await encryptNote({ amount: xferAmt, blinding: xferBld, memo: "hello bob" }, bobJub.pubkey);
  await (await janusFlow.shieldedTransfer(
    bobSigner.address, xferProof.pubSignals.map(x => x), flatProof(xferProof), noteC, noteEph.x, noteEph.y
  )).wait(1);
  aliceV -= xferAmt; aliceR = newAliceR;

  // 5. Bob drains inbox + decodes note
  const drained = await inboxBob.drainBatch.staticCall(1);  // static call to get return value
  await (await inboxBob.drainBatch(1)).wait(1);

  if (drained.length > 0) {
    const note = drained[0];
    const decoded = await decryptNote(
      Buffer.from(ethers.getBytes(note.ciphertext)),
      { x: note.ephPubkeyX, y: note.ephPubkeyY },
      bobJub.privkey
    );
    console.log("Decoded note:", decoded);
    // note.depositor = "0xA64340..." (JanusFlow proxy) → FLOW token
  }

  // 6. Unwrap 0.7 FLOW
  const unwrapAmt   = 7n * 10n**18n / 10n;
  const unwrapBld   = await randomScalar();
  const residualBld = await randomScalar();
  const adProof     = await generateAmountDiscloseProof({ amount: unwrapAmt, blinding: unwrapBld, nonce: 0n });
  const xfProof     = await generateProof({ old_value: aliceV, old_blinding: aliceR, transfer_value: unwrapAmt, transfer_blinding: unwrapBld, new_blinding: residualBld });
  const { ciphertext: rC, ephemeralPubkey: rEph } = await encryptNote({ amount: aliceV - unwrapAmt, blinding: residualBld }, aliceJub.pubkey);
  await (await janusFlow.unwrap(
    unwrapAmt, aliceSigner.address,
    [adProof.pubSignals[1], adProof.pubSignals[2]],
    flatProof(adProof), xfProof.pubSignals.map(x => x), flatProof(xfProof),
    rC, rEph.x, rEph.y
  )).wait(1);
}

main().catch(console.error);
```
